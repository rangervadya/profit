## Исправление v5.3.4 — даты, толщина стенки, сетка 6.1 и динамические фотографии

- Доработана маска ввода даты `ДД.ММ.ГГГГ`: позиция курсора рассчитывается по количеству цифр слева, поэтому вставка точек не съедает цифры при быстром наборе/редактировании. Добавлена проверка реальной календарной даты до отправки формы; календарь и клавиатурный ввод работают совместно.
- Поля «Минимальная толщина стенки» и «Максимальная толщина стенки» записываются в таблицу раздела 5.2.1 как нативный текст PDF размером 12 pt и проверяются в редактируемом DOCX. Для отдельных четырёх участков Приложения 11 остаются собственные значения толщины — они не копируются автоматически из общего поля, чтобы не подменять замеры.
- Исправлена сетка таблицы раздела 6.1: нижняя граница объединённой ячейки «Внутренний газопровод» проходит только по первому и последнему столбцам, как в оригинале; последующие разделители остаются непрерывными.
- Фотографии выбираются динамически. После выбора изображения появляется следующий ряд; кнопка «Добавить фотографию» также добавляет строку вручную. Первые 20 фото занимают исходные слоты, последующие попадают в дополнительные фотолисты. Каждая фотография ограничена 15 МБ, общий multipart-запрос — 512 МБ; при превышении лимита интерфейс получает понятную ошибку.
- При очистке формы динамические ряды фотографий сбрасываются до одного пустого поля. Теги образов/пакетов обновлены до v5.3.4.

## Исправление v5.3.1 — нативный редактируемый Word и типографика

- Общий механизм замены PDF-текста теперь использует размер и начертание исходного текстового фрагмента, а не маленький резервный размер из вызова функции. Для длинных подстановок допускается только ограниченное уменьшение кегля; при этом расширяется допустимая область строки.
- Переработаны поля УЗТ и Приложения 5: размеры модели/заводского номера/даты поверки ближе к исходной типографике, табличные значения подбираются под высоту ячеек. Заголовки, сведения о специалистах, подписи и протокольные строки приведены к размерам окружающего текста.
- Текст пояснения проверки герметичности и абзац остаточного ресурса формируются целиком кеглем около 12 pt, чтобы не смешивать мелкие цифры с крупным окружающим текстом.
- Основной экспорт DOCX формирует обычные редактируемые абзацы и нативные таблицы Word. Фотографии, схемы и подлинные сканы остаются отдельными изображениями, которые можно перемещать, удалять и заменять. Текст внутри подлинного скана не становится редактируемым без исходного цифрового документа либо OCR с ручной проверкой.
- Размер текста в ячейках Word теперь выводится из конкретных текстовых фрагментов исходного PDF, а не из общей медианы таблицы и не ограничивается прежним максимумом 10.5 pt. Восстанавливаются извлекаемые подписи в ячейках, которые PDF table detector помечал как пустые, включая сложные заголовки.
- Убрана из пользовательского интерфейса альтернативная VML-вёрстка Word, которая могла неправильно отображать повернутые заголовки в LibreOffice. Кнопка Word теперь однозначно создаёт документ с редактируемыми абзацами и таблицами; PDF используется для сохранения фиксированной вёрстки.
- Удалены старые placeholder-изображения из незаполненных фотослотов. Добавлены регрессионные проверки размера заменяемого текста, кириллицы, 49 страниц, сохранности схем и структуры редактируемого DOCX.

### Экспорт Word в v5.3

- Кнопка **«Word — редактируемый текст»** создаёт DOCX с обычными абзацами и таблицами Word; не создаётся полноразмерная фотография каждой страницы.
- Фото, схемы и сканы являются отдельными объектами изображения. Изображения можно удалять/заменять, но текст, который существует только внутри скана, не редактируется как слова без OCR или исходного файла.
- Страницы и расположение элементов могут отличаться от PDF, поскольку текст и таблицы переразмещаются средствами Word. Для оригинальной фиксированной вёрстки используется PDF.
- Размеры шрифта в ячейках таблиц считываются по конкретным исходным span-элементам PDF; снято глобальное ограничение 10.5 pt, которое уменьшало часть текста.

## Что изменено в v5.1

- Добавлен отдельный React + TypeScript + Vite 7 frontend в `frontend/`.

### Состояние миграции UI

Это намеренная переходная прослойка, чтобы первая контейнерная версия не потеряла работающие сценарии. Следующий этап миграции — перенос секций формы в React по одной, с сохранением тестов PDF.

## Запуск через Docker Compose (рекомендуется)

Требуются Docker Engine / Docker Desktop с Compose plugin.

1. Скопируйте `.env.example` в `.env`.
2. Измените `POSTGRES_PASSWORD` на пароль для вашей установки. Для простого URL в текущей настройке используйте буквы, цифры и `_`.
3. В корне проекта выполните:

```bash
docker compose up --build -d
```

4. Откройте <http://localhost:8080>.
5. Посмотреть логи:

```bash
docker compose logs -f backend frontend nginx db
```

6. Остановить сервисы, сохранив данные PostgreSQL:

```bash
docker compose down
```

Чтобы удалить также данные БД, применяется `docker compose down -v` — это удалит volume базы и журнал формирований.

## Нативный запуск без Docker

Требуются Python 3.12+ и Node.js 24+. На macOS самый простой способ — запустить скрипт из корня распакованного проекта. Скрипт проверяет состояние Docker Engine: если Docker Desktop закрыт или демон недоступен, приложение автоматически запускается нативно.

- macOS, всегда без Docker: `chmod +x start_mac_local.command && ./start_mac_local.command`
- macOS, автоматический выбор Docker/локального режима: `./start_mac.command`
- Linux: `./start_linux.sh`
- Windows: `install_and_run.bat`

В локальном режиме backend запускается на `127.0.0.1:8765`, React/Vite frontend — на `127.0.0.1:5173`. Без `DATABASE_URL` приложение работает без PostgreSQL: индикатор покажет «Локальный режим», журнал формирований останется пустым.

### Ручной запуск из корня проекта (macOS/Linux)

```bash
# Терминал 1 — Backend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
unset DATABASE_URL
VDGO_HOST=127.0.0.1 VDGO_PORT=8765 VDGO_NO_BROWSER=1 python app.py

# Терминал 2 — Frontend
npm install
npm run dev
```

Откройте `http://127.0.0.1:5173`. Команды выполняются из корня `905_pdf_automation_v5`, где находятся корневые `app.py`, `requirements.txt` и `package.json`. Не используйте путь `~/Downloads/...`, если проект распакован в другое место: сначала перейдите в фактическую папку проекта либо запустите `start_mac_local.command` двойным кликом в Finder.

## Важные ограничения

- В среде создания проекта Docker CLI отсутствует, поэтому сами контейнеры здесь не запускались. Dockerfile/Compose проверены статически; реальный `docker compose up --build` нужно выполнить на компьютере с Docker.
- Пакеты npm не удалось установить в среде сборки из-за тайм-аута доступа к npm registry. Docker build скачает зависимости при наличии сети; локальный `npm install` должен выполняться в сети с доступом к npm.
- PDF всё равно требует приёмочного просмотра всех 49 страниц на реальных данных. Схемы Приложения 2 восстановлены из исходного PDF; сканы актов/удостоверений/протоколов на страницах 31–36 и 41–47 загружаются актуальными файлами или явно исключаются.
- Инженерные измерения, расчёт ресурса, подписи и правомерность итогового вывода должны быть подтверждены уполномоченным специалистом.

## Важное ограничение

Это автономный презентационный прототип SCADA. Значения начального проекта демонстрационные; реальных датчиков, ПЛК, Modbus, OPC UA или MQTT он сам по себе не опрашивает и оборудованием не управляет. Для подключения физического оборудования потребуется сервер/шлюз, драйвер протокола, карта тегов и проверенная инженерная архитектура.
